# RouteX 3.4.3

## Что изменено

- Удалены уведомления о новой upstream-версии tg-ws-proxy: строка в TG Proxy, красная точка вкладки, всплывающее уведомление в трее и отдельная проверка upstream-релиза.
- Settings → Routing · Configs → Rule editor: таблица упорядоченных правил. Добавление, редактирование, включение/отключение, удаление, перемещение вверх/вниз.
- Условия: домены (domain, full, keyword, regexp, geosite), IP/CIDR/geoip, имя процесса/полный путь, все соединения; дополнительные фильтры TCP/UDP и порта/диапазона портов.
- Действия: direct, proxy (VPN), block. Первое совпадение выигрывает. Отдельно задаётся маршрут для несовпавшего трафика, включая Direct при пустой таблице.
- Кнопка RU + current lists формирует черновик: RU-домены/IP → Direct, Exclude → Direct, Include → VPN. Списки копируются на этот момент; дальнейшие изменения старых списков таблицу не меняют.
- Редактор по умолчанию выключен. При включении он заменяет Include/Exclude для VLESS/VMess/Trojan в Configs. Вторичные правила RU/рекламы в Xray для этого режима отключены, чтобы они не переопределяли таблицу. WireGuard и подписки редактор не использует.
- Служебные процессы, локальные сети, пробник VPN и режим аварийного восстановления «только Строго VPN» имеют фиксированные служебные правила. Об этом сказано над таблицей.
- Редактирование и сохранение блокируются при активном/подключающемся VPN. Настройки применяются при следующем подключении.
- В настройках добавлен IPv4-only TUN для Configs (по умолчанию включён). Из inbounds удаляется IPv6-адрес, AAAA получает пустой успешный ответ; IPv6-пакеты, попавшие в TUN, отклоняются. strict_route остаётся включённым. Привязки адаптеров Windows приложение не переключает.
- DNS через VPN действительно меняет DNS fallback в Configs. Доменные Exclude получают local до правил Include. Включён reverse_mapping для сопоставления доменов с адресами, полученными через DNS TUN. Имя VPN-сервера получает локальный bootstrap DNS, чтобы не зависеть от ещё не установленного VPN.
- При включённом DNS через VPN запросы без определяемого исходного процесса (включая svchost) по умолчанию идут через VPN. Это не гарантирует определение приложения: DNS для исключённого процесса тоже может идти через VPN, если запрос сделал svchost. Явные доменные Direct-правила используют local. IP/порт/транспортные условия DNS-запрос имени повторить не может.
- Окно проверки маршрута читает сгенерированные runtime-конфиги sing-box и Xray, включая RU bypass старого режима. Если для выбора правила недостаёт порта/транспорта/домена/адреса, показывает Unknown вместо выдуманного маршрута. Это прогноз по правилам, а не трассировка реального соединения.
- EnsureTun в пути подписок сохраняет работающий sing-box только при совпадении полного конфига. Изменение SOCKS-порта пересоздаёт TUN. При ошибке первоначального старта TUN этот путь не возвращает успешное подключение.
- Перед запуском sing-box выполняется check; немедленное завершение процесса возвращается как ошибка запуска.
- Сохранены изменения 3.4.2: блокировка правок Include/Exclude при VPN, свободное перемещение виджета, отсутствие Reset layout в трее.
- Допустимые TLS/VLESS-конфиги и allowInsecure не изменены; новых предупреждений/запретов для них нет.

## Проверка

- Сборка .NET Framework 4.8 проходит. Два прежних предупреждения PagesServers.cs (CS0162, CS0649) остаются.
- 47 проверок предыдущей регрессии и 39 новых проверок маршрутизации/DNS/сохранения/редактора проходят.
- Перезапуск при смене SOCKS-порта проверен отдельным офлайн-процессом-заглушкой, который не создаёт сокеты, маршруты или адаптеры.
- Реальный sing-box 1.14.4 принимает сгенерированные конфиги через check; Xray 26.10.29 принимает пример через run -test. VPN при этих проверках не запускался.
- Проверен рендер таблицы в светлой и тёмной теме.
- Работа сайтов и отсутствие утечек на проблемном удалённом компьютере этой проверкой не подтверждены. Нужна проверка именно там, с его сетью и настройками браузера (включая Secure DNS/DoH).

## Как попробовать

1. Сделать резервную копию папки config. Выключить VPN и полностью закрыть текущий RouteX/NetProbe.
2. Заменить запускаемый EXE рядом с существующими папками xray, singbox, zapret и config. RouteX.exe и NetProbe.exe в пакете одинаковы; выбрать используемое имя.
3. Settings → Routing · Configs → Rule editor → RU + current lists. Проверить таблицу и Unmatched traffic, включить Use ordered rules, нажать Save.
4. Подключиться через Configs. Direct проходит через DPI только при отдельно включённом DPI и совпадении с его правилами.
