NetProbe 3.3.6 — DPI no longer breaks the VPN connection, fewer tunnel restarts
## Fix: VPN dropped when DPI (winws) was on
- winws processed NetProbe's own connection to the VPN server. With some strategies this broke the VLESS / REALITY handshake (`TLS handshake failed: Connection was reset`), the VPN "stopped responding", NetProbe switched to DPI, and it could repeat in a loop.
- The VPN server addresses (primary and enabled backup tunnel, active subscription server; domains are resolved) are now always in the winws exclusion list, so DPI never touches VPN traffic.

## Fewer tunnel restarts while editing lists
- Every change in Include / Exclude restarted the tunnel at once, so adding several domains in a row restarted it again and again (a few seconds without VPN each time, "SAME ROUTE" flashes). Changes made within 2 seconds of each other are now applied with one restart.

## Log
- "Channels are split" is no longer logged when the VPN probe just failed (it used to print the same IP for VPN and direct).
