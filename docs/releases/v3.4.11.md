RouteX 3.4.11 — sites open faster through VLESS / VMess / Trojan

- Sites behind a CDN (Google, YouTube, Cloudflare, Akamai and others) open noticeably faster through a server, both in TUN and in system proxy mode. The server now receives the site's name, not an IP from your local DNS, so it resolves the site itself and connects to the CDN node closest to it, as v2rayN does. Before, it went to the node picked for your country, and every request took the long way.
- System proxy mode no longer makes a DNS lookup before every new site (domain strategy AsIs, as in v2rayN). RU sites still go direct by their domains.
- TUN: QUIC (UDP 443) to the server is refused immediately, so browsers switch to TCP at once instead of waiting for a QUIC answer that never comes (xray drops UDP 443 with flow Vision). `TunRejectQuic=0` in settings.ini turns this off.
- TUN: DNS through the server uses DoH over one kept connection instead of a new TCP connection with a full handshake for every query.
- New: rule editor in v2rayN style (Settings → Engine → Rule editor, off by default): rule sets, Domain / IP / Process rules, import and export in the v2rayN format, RU geodata and RU sites detection.

Fully disconnect the VPN and close RouteX before replacing the executable. RouteX.exe and NetProbe.exe are identical.
