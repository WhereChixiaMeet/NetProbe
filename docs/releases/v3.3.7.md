NetProbe 3.3.7 — VLESS tunnel starts even if an old xray is stuck on its port
## Fix: "The tunnel's xray exited right away" after a crash
- xray and sing-box are started so that they survive NetProbe exiting (needed for updates without a VPN drop). After an abnormal exit (crash, Task Manager, failed update) the old tunnel xray could stay running and keep the tunnel port (`TunnelSocksPort`, 10828 by default). The new xray then could not start, the VLESS / VMess / Trojan tunnel never came up, NetProbe fell back to DPI, and the monitor showed SAME ROUTE.
- Before starting the tunnel NetProbe now checks its ports. A stuck `xray.exe` from the NetProbe folder that this run did not start is closed automatically (logged). If another program holds the port, the log and status say which one (name + PID) instead of "xray exited right away".
- Subscription ports are no longer moved onto the tunnel ports when they are busy.
